# Chat Service — Техническое задание

> **Статус:** 🔴 В разработке  
> **Назначение:** Чаты, сообщения, звонки, медиа-галерея

---

## 1. Бизнес-функции

### Core — Чаты
- DIRECT чат между двумя пользователями (создаётся при первом сообщении)
- Список чатов пользователя с превью последнего сообщения
- Отметка о прочитанном (unread count)
- Real-time доставка сообщений (WebSocket)
- Online/offline статус собеседника

### Core — Сообщения
- Отправка текстовых сообщений
- Отправка файлов (изображения, видео, аудио, документы)
- Пересылка (forward) сообщений в другой чат
- Редактирование своего сообщения
- Удаление для всех (soft delete — текст заменяется на "сообщение удалено")
- Удаление для себя (сообщение скрывается только у удалившего)
- Link preview — автоматическое формирование превью ссылки (OG-теги)
- Поиск по тексту сообщений в чате

### Core — Медиа
- Аудиоплеер с waveform (визуализация звука), регулировкой скорости, перемоткой
- Видеоплеер — встроенный, с fullscreen
- Видеосообщения-"кружки" (до 60 сек) с круглым маской
- Внутричатовая галерея: вкладки Медиа / Файлы / Аудио / Видео / Ссылки

### Уровень 2 — Групповые чаты ★
- Создание группы (название, аватар, участники)
- Приглашение новых участников
- Роли: ADMIN, MODERATOR, MEMBER
- Кик участника, выход из группы
- Mute чата / блокировка участника
- Системные сообщения (user joined, user left, role changed)

### Уровень 3 — Звонки ★
- P2P аудио-звонок
- P2P видео-звонок
- Групповые аудио/видео звонки
- Signal через WebSocket (offer/answer/ICE)

## 2. Ключевые бизнес-сценарии

### Direct чат
```
1. Пользователь находит собеседника через поиск
2. Открывает чат — чат создаётся, если не существовал
3. Отправляет сообщение — собеседник получает через WebSocket
4. Собеседник видит typing indicator
5. Сообщения хранятся с курсорной пагинацией
```

### Отправка файла
```
1. Пользователь выбирает файл (изображение / видео / аудио / документ)
2. Файл загружается с отображением прогресса
3. После загрузки — асинхронная генерация превью / waveform
4. В чате отображается превью / плеер
5. Файл доступен в соответствующей вкладке галереи
```

### Звонок
```
1. Пользователь нажимает кнопку звонка в шапке чата
2. Собеседнику приходит входящий вызов (через WebSocket + push)
3. Принятие вызова → P2P WebRTC соединение
4. Завершение → статистика звонка
```

### Редактирование и удаление
```
1. Контекстное меню на своём сообщении: редактировать / удалить
2. Редактирование — инлайн, появляется метка "изменено"
3. Удаление для всех — сообщение исчезает у всех
4. Удаление для себя — сообщение исчезает только у удалившего
```

---

## 3. Важные нюансы

- **Поиск сообщений** — индексируются в Meilisearch асинхронно (через событие после создания)
- **Link preview** — парсинг Open Graph тегов, асинхронно, не блокирует отправку
- **Unread count** — хранится в `lastReadMessageId` у участника чата. При входе — "N новых сообщений"
- **Soft delete** — сообщение не удаляется физически, выставляется флаг `isDeleted`. Текст очищается.
- **Типы сообщений** — TEXT, IMAGE, AUDIO, VIDEO, VOICE, FILE, SYSTEM
- **Waveform** — генерируется на клиенте при загрузке аудио через Web Audio API
- **Видеокружки** — до 60 секунд, формат MP4/WebM/QuickTime, upload как CIRCLE

## 4. Acceptance Criteria / Expected Behavior

### TC-1.1: Создание Direct чата и отправка текстового сообщения

**Preconditions:**
- Пользователь A авторизован, находится на странице чатов (/chats)
- Пользователь B существует в системе

**Flow:**
1. Пользователь A вводит имя пользователя B в строку поиска
   → Через 300ms после остановки ввода появляются результаты (если ≥2 символов)
   → В результатах: аватар (или инициалы), имя, displayName
2. Пользователь A кликает на пользователя B
   → Если direct чат уже существует: открывается окно чата
   → Если нет: создаётся чат, открывается пустое окно
3. Пользователь A вводит текст "Привет!" в поле ввода
   → Кнопка отправки активна только если поле не пустое
4. Пользователь A нажимает Enter (или кнопку отправки)
   → Сообщение появляется в чате (статус: серый — sending)
   → Поле ввода очищается
5. Через <1с статус меняется на доставлено (белый фон + время)
   → В списке чатов у чата с B обновилось превью: "Вы: Привет!"
6. Пользователь B (если онлайн): получает сообщение через WebSocket
   → Если B в этом чате: сообщение появляется без перезагрузки
   → Если B не в чате: в списке чатов +1 unread, превью обновилось
   → Если B не в приложении: push-уведомление "A: Привет!"

**Ошибки:**
- **Нет соединения:** сообщение остаётся серым, иконка ⚠️, кнопка "Повторить" при клике
- **Чат удалён / пользователь заблокирован:** ошибка "Не удалось отправить сообщение"
- **Пустое сообщение:** кнопка отправки disabled

**Edge cases:**
- Сообщение из 4000+ символов: блокируется (max 4000)
- Быстрая отправка 50+ сообщений: все отправляются, порядок сохранён

### TC-1.2: Редактирование сообщения

**Preconditions:**
- Пользователь A отправил сообщение с текстом "Привет!"
- Сообщение доставлено (статус: белый)

**Flow:**
1. Пользователь A нажимает ✏️ на своём сообщении (контекстное меню / долгий тап)
   → Сообщение переходит в режим редактирования
   → Текст сообщения в поле ввода, курсор в конце
   → Появляется кнопка "Отмена" / Escape возвращает как было
2. Пользователь A меняет текст на "Привет! Как дела?" и сохраняет
   → Сообщение обновляется: новый текст, метка "изменено" (edited)
   → Время отправки не меняется
   → WebSocket отправляет `message:edited` всем в комнате
3. Собеседник B видит: сообщение изменилось + метка "изменено"

**Ошибки:**
- **Редактирование через 30+ минут после отправки:** кнопка редактирования неактивна (таймаут)
- **Редактирование чужого сообщения:** кнопки редактирования нет вообще
- **Пустой текст после редактирования:** кнопка сохранения disabled
- **Сообщение уже удалено:** редактирование недоступно

**Edge cases:**
- Быстрое редактирование несколько раз: работает, метка edited остаётся
- Редактирование во время отправки (sending): кнопка редактирования неактивна

---

### TC-1.3: Удаление сообщения

**Delete for all:**
1. Пользователь A → контекстное меню → "Удалить" → "Для всех"
   → Сообщение заменяется на "Сообщение удалено" (только текст, без автора)
   → У всех участников чата: то же самое
   → WebSocket: `message:deleted`
   → Если у сообщения был файл: файл не удаляется (остаётся в галерее)
2. **Ошибка:** удаление сообщения старше 24ч → кнопка "Для всех" неактивна

**Delete for me:**
1. Пользователь A → контекстное меню → "Удалить" → "Для меня"
   → Сообщение исчезает из чата у A
   → У B: сообщение остаётся как было
   → Если A захочет увидеть удалённое: нет UI для этого
2. **Ошибка:** удаление для меня уже удалённого для себя → сообщения уже нет, ничего не происходит

**Восстановление:**
- "Сообщение удалено" нельзя восстановить (hard-delete for viewer)
- Удаление для себя: необратимо (без корзины)

### TC-1.4: Link Preview

**Preconditions:**
- Пользователь A вводит текст, содержащий URL

**Flow:**
1. A отправляет сообщение "Смотри https://example.com/article"
   → Сообщение отправляется сразу (не ждём preview)
2. Через 1-3 секунды под сообщением появляется карточка preview:
   - Заголовок (og:title)
   - Описание (og:description) — до 2 строк
   - Изображение (og:image) — справа или сверху
   - Домен (example.com)
   → Карточка кликабельна: открывает URL в новой вкладке
3. Если ссылка некорректная или OG тегов нет:
   → Карточка не показывается, сообщение остаётся как обычный текст со ссылкой
   → Ссылка кликабельна (открывается в новой вкладке)

**Ошибки:**
- **Сервер парсинга недоступен:** сообщение отправлено, preview не появился
- **HTTPS → HTTP mixed content:** preview не загружается, ссылка работает
- **Очень длинный URL:** preview показывается, в карточке — домен, не полный URL

### TC-1.5: Unread Count

**Preconditions:**
- У пользователя A есть 5 чатов
- В чате с B: 3 непрочитанных сообщения

**Flow:**
1. Пользователь A видит список чатов
   → У чата с B: жирный текст (непрочитанное), badge с "3" справа
   → Превью показывает последнее сообщение от B
   → Другие чаты без новых: обычный текст, без badge
2. Пользователь A открывает чат с B
   → Badge "3" исчезает
   → Чат перестаёт быть жирным
   → Сообщения скроллятся вниз, к самому новому
   → Если A давно не заходил: кнопка "N новых сообщений" вверху
3. Пользователь A нажимает кнопку "3 новых сообщения"
   → Скролл к первому новому сообщению
   → Сообщения подсвечиваются и постепенно сбрасывают подсветку

**Edge cases:**
- **Пользователь видит чат через WebSocket в реальном времени:** unread не накапливается, сообщение считается прочитанным
- **Пользователь заходит, читает, выходит, приходит новое:** badge показывает только новые после последнего прочитанного

---

### TC-1.6: Аудио плеер + Waveform

**Preconditions:**
- В чате есть сообщение с аудиофайлом (категория AUDIO или VOICE)

**Flow:**
1. Пользователь видит аудиосообщение в чате
   → Для VOICE: компактный плеер (аватарка отправителя, длительность, waveform)
   → Для AUDIO: полноценный плеер (название файла, waveform, прогресс, время)
2. Пользователь нажимает Play
   → Кнопка меняется на Pause
   → Waveform анимируется (бежит линия прогресса по волнам)
   → Текущее время обновляется (0:05 / 3:30)
3. Пользователь перематывает кликом по waveform
   → Воспроизведение продолжается с выбранной позиции
4. Пользователь меняет скорость: 1x → 1.5x → 2x → 0.5x
   → Голос ускоряется/замедляется, питч сохраняется
5. Пользователь нажимает Pause
   → Воспроизведение останавливается, прогресс сохраняется
6. Пользователь выходит из чата и заходит обратно
   → Прогресс сброшен

**Ошибки:**
- **Формат не поддерживается браузером:** плеер показывает "Формат не поддерживается"
- **Файл ещё обрабатывается (PROCESSING):** плеер disabled, метка "Обработка..."

---

### TC-1.7: Видео плеер + кружки

**Preconditions:**
- В чате есть сообщение с видео (VIDEO) или кружком (CIRCLE)

**Flow (Video):**
1. Пользователь видит сообщение с видео: thumbnail + кнопка Play
2. Нажимает Play
   → Видео начинает воспроизводиться в чате (inline)
   → Контролы: play/pause, прогресс, громкость, fullscreen
3. Нажимает fullscreen
   → Видео на весь экран
4. При скролле: видео с muted авто-плееем (если visible), иначе ставится на паузу

**Flow (Circle):**
1. Пользователь видит круглое видео (как в Telegram)
   → Авто-воспроизведение (muted, loop) при скролле
   → Без контролов
   → Размер: ~150x150px
2. Пользователь тапает на кружок
   → Открывается полноэкранный плеер со звуком
   → Можно переслать / сохранить
3. Пользователь закрывает fullscreen
   → Возвращается к списку сообщений

### TC-1.8: Внутричатовая галерея

**Preconditions:**
- В чате есть 20+ файлов разных типов (фото, видео, аудио, документы, ссылки)

**Flow:**
1. Пользователь открывает чат → тапает на имя / аватар в шапке
   → Открывается галерея чата
2. По умолчанию — вкладка "Медиа"
   → Сетка из миниатюр (3 колонки)
   → Скролл — пагинация (Load more / infinite scroll)
3. Пользователь переключается на "Файлы"
   → Список: иконка + имя + размер + дата
   → Клик → скачивание
4. Пользователь переключается на "Ссылки"
   → Список: favicon + домен + заголовок + описание
   → Клик → открытие ссылки
5. Пользователь переключается на "Аудио"
   → Список: название, длительность, дата
   → Можно слушать прямо из галереи

**Edge cases:**
- **Пустая вкладка:** отображается EmptyState "Нет медиа в этом чате"
- **Чат без файлов:** все вкладки показывают EmptyState

### TC-1.9: Поиск по сообщениям

**Preconditions:**
- В чате 1000+ сообщений, среди которых есть "встреча в пятницу"

**Flow:**
1. Пользователь нажимает 🔍 в шапке чата
   → Появляется поисковая строка, клавиатура активна
2. Вводит "пятница"
   → Через 300ms после остановки ввода: результаты поиска
   → Каждый результат: текст сообщения (с подсветкой "пятница"), дата, имя отправителя
3. Пользователь кликает на результат
   → Чат скроллится к этому сообщению
   → Сообщение подсвечивается (желтый фон) → затухает через 2с
4. Пользователь очищает поиск / закрывает
   → Возврат к обычному чату

**Ошибки:**
- **Поиск < 2 символов:** игнорируется, ничего не ищется
- **Ничего не найдено:** EmptyState "Ничего не найдено"
- **Специальные символы:** экранируются или игнорируются

---

### TC-1.10: Forward сообщений

**Preconditions:**
- У пользователя есть чат A с сообщениями и чат B

**Flow:**
1. Пользователь выбирает 1+ сообщений в чате A (долгий тап / чекбоксы)
   → Выбранные подсвечиваются, появляется панель действий
2. Нажимает "Переслать" (→)
   → Открывается список чатов (поиск по чатам)
3. Выбирает чат B
   → Сообщения появляются в чате B с меткой "Переслано из чата A"
   → Отправитель: тот, кто переслал
4. Получатели в чате B видят: сообщения + метка "Переслано"

**Ошибки:**
- **Выбор > 50 сообщений:** кнопка "Переслать" неактивна (лимит)
- **Выбор сообщений из разных чатов:** только из одного чата
- **Чат B удалён:** ошибка "Чат не найден"

### TC-2.1: Групповой чат ★

**Preconditions:**
- Пользователь A (создатель) авторизован
- Пользователи B, C, D существуют

**Flow:**
1. A → кнопка "Создать группу"
   → Модалка: название группы, поиск участников
2. A вводит "Рабочие вопросы", добавляет B, C
   → Можно изменить аватар группы
3. A нажимает "Создать"
   → Группа создана, A — ADMIN
   → B и C получают чат в списке, системное сообщение: "A создал(а) группу"
4. A добавляет D через "Добавить участника"
   → D получает чат, системное: "A добавил(а) D"
5. B покидает группу
   → Системное: "B покинул(а) группу"
   → B больше не видит чат в списке

**Роли и модерация:**
1. A назначает C — MODERATOR
   → Системное: "A назначил(а) C модератором"
2. C может: кикать MEMBER'ов, но не ADMIN'ов
3. A может кикнуть любого
4. Кикнутый участник: больше не видит чат, не может присоединиться без приглашения

### TC-3.1: P2P аудио-звонок ★

**Preconditions:**
- Пользователи A и B онлайн, в чате друг с другом
- Оба дали разрешение на микрофон

**Flow:**
1. A нажимает 🎧 в шапке чата
   → У A: overlay "Звонок...", слышен гудок
   → У B: overlay входящего звонка (аватар A, имя, кнопки: Принять / Отклонить)
   → Если B не в приложении: push "A вызывает вас..."
2. B нажимает "Принять"
   → A: гудок прекращается, overlay "00:05" (таймер)
   → B: overlay "00:05"
   → Аудио-поток P2P
3. A нажимает "Завершить"
   → Звонок завершён, overlay закрыт
   → B: звонок завершён, overlay закрыт
4. **Если B отклонил:**
   → A: "B не ответил(а)"
   → B: ничего

**Ошибки:**
- **Нет доступа к микрофону:** кнопка звонка неактивна, tooltip "Нет доступа к микрофону"
- **B в статусе DND или невидимка:** звонок не проходит или идёт сразу в голосовую почту (TBD)
- **Потеря соединения:** звонок прерывается, overlay "Соединение потеряно"
