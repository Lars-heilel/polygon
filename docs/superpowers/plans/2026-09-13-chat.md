# chat-service Implementation Plan (SPEC-6, тяжёлый)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Оживить BIGINT-схему: string↔bigint трансляция в репо, `directKey`, `hasLink`, частичный unique `clientId`, дельта-синк, фронтовые realtime-патчи. Prisma уже сделана (коммит `f336b57`).

**Architecture:** Слой трансляции — ТОЛЬКО `chat.prisma.repo.ts` (границы Prisma): внутрь — `BigInt`,
наружу — decimal-строки. Сервис/gateway/фронт продолжают говорить строками. Wire-формат
совместим: normalizer и gateway ответы через zod не валидируют (проверено), decimal-ID —
обычные строки для всего стека.

**Tech Stack:** NestJS + Prisma + Socket.IO gateway + Redis-кэши, React Query infinite,
zod, Jest (`jest.mock('@org/core')`-фабрики), Nx из корня.

**Spec:** `docs/superpowers/specs/2026-09-13-chat-design.md` (§3 — факт реализации)

## Global Constraints

- Nx только из корня; `--testPathPatterns=`; `npm` эксклюзивно.
- Контракты first; маршруты `API_ROUTES`; паттерны из `CHAT_PATTERNS`.
- Существующие спеки (`chat.prisma.repo.spec` 19 кейсов, `chat.service.spec`, gateway/socket спеки)
  — зелёные до и после; фикстуры message-ID переводятся на numeric-строки (`'101'`), т.к. домен
  изменился (не-numeric ID больше невозможны).
- Логи: `eventType` + presence-флаги (сервис уже соответствует).
- `nx sync` дважды после межпакетных импортов.
- Частичный unique — raw-миграция (Prisma не умеет partial unique в схеме).

Трансляция — только здесь. Хелперы вверху файла:

```ts
const toMessageId = (id: string): bigint => {
  try {
    return BigInt(id);
  } catch {
    throw new BadRequestException('Invalid message id');
  }
};
const fromMessageId = (id: bigint): string => id.toString();
const toMessage = (row: PrismaMessageRow): Message => ({
  ...row,
  id: fromMessageId(row.id),
  // attachments[].messageId/fileSizeSnapshot, forwardContext ids — аналогично;
  // fileSizeSnapshot: row.fileSizeSnapshot === null ? null : Number(row.fileSizeSnapshot),
});
```

(`BadRequestException` уже импортирован в файле. Типы строк Prisma — через
`Prisma.MessageGetPayload` или структурные; выбрать по факту генерации клиента.)

Правила:
- Все `where: { id }`, `cursor: { id }`, `id: { in }`, `upsert messageId_userId`,
  `lastMessageId/lastReadMessageId` записи — через `toMessageId`.
- Все возвраты сообщений/чатов/мемберов — через мапперы (`fromMessageId`,
  `fileSizeSnapshot → Number|null`, `lastMessageId: row.lastMessageId === null ? null : fromMessageId(...)`).
- `createMessageWithTouch/createMessageWithRelations`: `hasLink` из入 data (Task 3 передаёт),
  интерфейс `CreateMessageData` дополнить `hasLink?: boolean`.
- `findDirectChatByKey(directKey)` — новый метод + интерфейс (гонка createDirectChat).
- `findMessagesDelta(chatId, userId, since: Date, sinceId: string | null, take: number)`:
  changed = visible + `(updatedAt > since OR (updatedAt == since AND id > sinceIdBigint))`,
  order asc, take; deletedIds = `messageDeletion` rows пользователя с `deletedAt > since`
  (map `fromMessageId`); возврат `{ messages: mapped, deletedIds }`.
- `countUnreadMessages`: `id: { gt: toMessageId(lastReadMessageId) }`.
- `markChatRead`: lookup + `lastReadMessageId: toMessageId(...)`; возврат маппированного мембера.
- `findMessagesByChat/findMediaMessagesByChat`: cursor → `toMessageId`, `nextCursor` уже строка
  (маппер), keyset `(createdAt, id)` без изменений.

Миграция partial unique:
1. Убрать `@@unique([chatId, clientId])` из схемы → `migrate dev` (генерит DROP CONSTRAINT).
2. Ручной файл `migrations/<ts>_chat_client_id_partial_unique/migration.sql`:

```sql
CREATE UNIQUE INDEX "messages_chat_id_client_id_key" ON "messages"("chat_id", "client_id") WHERE "client_id" IS NOT NULL;
```

3. `migrate dev` применяет. Имя индекса = имя снятого constraint (стабильность для Prisma).

Спеки: заменить message-ID фикстуры на numeric-строки (`'message-1'` → `'101'` и т.п.)
и exact-ассерты на `101n`; `objectContaining`-ассерты не трогать. Запускать сьют после
каждой группы правок, не в конце.
