# DB Phase (uuid v7 + Postgres 18) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Все id и ссылки — нативный `uuid` с генерацией `uuidv7()` на PG18.

**Architecture:** Сначала апгрейд PG 17→18 через dump/restore (data dir
несовместим), затем по одному сервису: правка схемы → `migrate dev --create-only`
→ проверка `USING` → применение → generate → тесты. Связей между БД нет,
порядок сервисов свободный.

**Tech Stack:** Postgres 18 (`postgres:18-alpine`, тег проверен), Prisma 7.5,
`dbgenerated("uuidv7()")` (встроен в PG18, расширения не нужны).

**Spec:** Утверждённые предложения 2026-10-02 (чат): все `@id` +
поля-ссылки → `@db.Uuid`; PK-дефолт → `dbgenerated("uuidv7()")`; тексты,
даты, enum, bool — не трогать; `clientId`, `tokenHash`, внешние строки —
остаются text.

## Global Constraints

- NPM only; новых npm-зависимостей нет.
- Миграции только через `prisma migrate dev --config prisma.config.ts` с cwd
  в корне либы (как `prisma-generate` в `package.json` либ); deploy-стиль
  (`migrate deploy`) — только как в `docker/demo/start.sh`, не для dev.
- TS не меняется (`@db.Uuid` остаётся `string`); zod `z.uuid()` принимает v7.
- Без секретов в логах; спеки в `__tests__/`; тесты из корня через `npm exec nx`.
- После задач: `affected --target=test` + `format:check` (свои файлы чистыми).
- Dev-БД: бэкап обязателен до любых разрушительных шагов; сервисы во время
  дауна PG будут сыпать ошибками реконнекта в лог — это шум, не чинить.

### Task 1: Postgres 17 → 18 (backup → fresh volume → restore)

**Files:**

  (`postgres:17-alpine` → `postgres:18-alpine`)

Базы: `polygon`, `polygon_auth`, `polygon_user`, `polygon_chat`,
`polygon_media`, `polygon_notification`. Volume: `polygon_postgres_data`.
Пароль: `POSTGRES_PASSWORD` из корневого `.env`.

- [ ] **Step 1: Снять счётчики до**

```bash
for DB in polygon_auth polygon_user polygon_chat polygon_media polygon_notification; do echo -n "$DB: "; PGPASSWORD="$(grep -E '^POSTGRES_PASSWORD=' .env | cut -d= -f2)" psql -h localhost -U polygon -d "$DB" -tAc "SELECT count(*) FROM (SELECT tablename FROM pg_tables WHERE schemaname='public') t JOIN LATERAL (SELECT 1) x ON true;" 2>/dev/null || echo "?"; done
```

Проще и точнее — записать counts ключевых таблиц:

```bash
PGPASS="$(grep -E '^POSTGRES_PASSWORD=' .env | cut -d= -f2)"
PGPASSWORD="$PGPASS" psql -h localhost -U polygon -d polygon_auth -tAc "SELECT 'credentials:'||count(*) FROM credentials;"
PGPASSWORD="$PGPASS" psql -h localhost -U polygon -d polygon_chat -tAc "SELECT 'message:'||count(*) FROM \"Message\";"
PGPASSWORD="$PGPASS" psql -h localhost -U polygon -d polygon_user -tAc "SELECT 'user:'||count(*) FROM \"User\";"
```

Записать цифры в отчёт (они понадобятся на Step 5).

- [ ] **Step 2: Полный бэкап**

```bash
mkdir -p /tmp/opencode && PGPASSWORD="$(grep -E '^POSTGRES_PASSWORD=' .env | cut -d= -f2)" docker compose exec -T postgres pg_dumpall -U polygon > /tmp/opencode/pg17-backup.sql && ls -la /tmp/opencode/pg17-backup.sql
```

Expected: файл ненулевого размера.

- [ ] **Step 3: Сменить тег и пересоздать volume**

```bash
sed -i 's/postgres:17-alpine/postgres:18-alpine/' docker-compose.yml docker/demo/docker-compose.yml && grep -n "postgres:1" docker-compose.yml docker/demo/docker-compose.yml
docker compose stop postgres && docker compose rm -f postgres && docker volume rm polygon_postgres_data && docker compose up -d postgres
```

Expected: обе строки показывают `postgres:18-alpine`; контейнер healthy
(`docker compose ps postgres`, `pg_isready`).

- [ ] **Step 4: Restore**

```bash
PGPASSWORD="$(grep -E '^POSTGRES_PASSWORD=' .env | cut -d= -f2)" docker compose exec -T postgres psql -U polygon -d postgres -f - < /tmp/opencode/pg17-backup.sql > /tmp/opencode/pg18-restore.log 2>&1; tail -3 /tmp/opencode/pg18-restore.log
```

`CREATE DATABASE` на уже созданные init-скриптом БД будет ругаться —
это нормально (psql продолжает, `\connect` цепляется к существующей пустой
и грузит данные). Если restore упал жёстко — смотреть лог, чинить точечно,
не катить дальше.

`SELECT version();` содержит `PostgreSQL 18`.

### Task 2: auth → uuid v7

**Files:**
- Modify: `libs/backend/auth/src/database/prisma/schema.prisma`
- Create (via migrate): `libs/backend/auth/src/database/prisma/migrations/<ts>_uuid_v7/migration.sql`
- Test: `npm exec nx -- test @org/auth` + `prisma validate`

**Interfaces:** Produces: паттерн миграции (create-only → USING → apply),
который Tasks 3–6 повторяют дословно.

- [ ] **Step 1: Правка схемы (только перечисленные строки)**

```prisma
model Credentials {
  id             String         @id @default(dbgenerated("uuidv7()")) @db.Uuid @map("id")
  ...
  bannedBy       String?        @db.Uuid @map("banned_by")
  ...
}
model OAuthAccount {
  id            String      @id @default(dbgenerated("uuidv7()")) @db.Uuid @map("id")
  ...
  credentialsId String      @db.Uuid @map("credentials_id")
  ...
}
model Session {
  id            String    @id @default(dbgenerated("uuidv7()")) @db.Uuid
  ...
  credentialsId String    @db.Uuid
  ...
}
```

НЕ трогать: `email`, `provider`, `providerId`, `tokenHash`, `passwordHash`,
тексты (`banReason`, `ip`, `country`, `os`, `browser`, `device`, `userAgent`),
`DateTime`, `Boolean`, `Role`, индексы/unique (имена те же).

- [ ] **Step 2: Validate + create-only миграция**

```bash
prisma validate --config prisma.config.ts && prisma migrate dev --create-only --name uuid_v7 --config prisma.config.ts
```

Run from: `workdir libs/backend/auth`.

- [ ] **Step 3: Проверить SQL (обязательно руками)**

Открыть `src/database/prisma/migrations/<ts>_uuid_v7/migration.sql`:
каждый `ALTER COLUMN ... TYPE` для id/ссылок обязан содержать
`USING "<col>"::uuid`. Если Prisma не сгенерировала `USING` — дописать
вручную в каждую такую строку. Каждый `SET DEFAULT` обязан быть
`uuidv7()`. FK внутри БД (Session→Credentials, OAuth→Credentials) кастятся
той же миграцией — порядок колонок не важен, Postgres перепишет.

- [ ] **Step 4: Применить + regenerate + тесты**

```bash
prisma migrate dev --config prisma.config.ts && prisma generate --config prisma.config.ts && npm exec nx -- test @org/auth 2>&1 | tail -3
```

Expected: миграция применена, generate ок, спеки PASS.

- [ ] **Step 5: Commit**

```bash
git add libs/backend/auth/src/database/prisma/
git commit -m "feat: auth ids to uuid v7"
```
