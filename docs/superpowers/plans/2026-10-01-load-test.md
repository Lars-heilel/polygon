# Load Test Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Построить повторяемый k6-набор в `infra/load`, отвечающий сколько VU/RPS держит Polygon.

**Architecture:** Node seed готовит `load_*` юзеров через Gateway HTTP, k6 (docker-образ `grafana/k6`) гоняет HTTP и WS сценарии с ramp и thresholds, метрики смотрим в `polygon-backend-overview`.

**Tech Stack:** k6 (только `docker run grafana/k6`, без npm-зависимостей), Node 22 `fetch` для seed/cleanup, Gateway `http://localhost:3000` + `ws://localhost:3000`.

**Spec:** `docs/superpowers/specs/2026-10-01-load-test-design.md`

## Global Constraints

- NPM only, `package-lock.json` — источник правды; k6 только как docker-образ, новых npm-зависимостей не добавляем.
- Маршруты только значения из `API_ROUTES` (`auth/register`, `auth/login`, `chats`, `chats/:id/messages`, `search/users`); тела только по zod-схемам `libs/common` (register: email+password по `PASSWORD_REGEX` + username min 2; login: email+password; send-message: TEXT требует text).
- Прод-код не меняем; новый код только в `infra/load`.
- Без секретов в логах — только `hasToken`/`hasUserId` флаги и `eventType`.
- Проверки после задач: `npm run format:check`; тесты гонять только из корня через `npm exec nx`.
- Throttle прод `60с/100` не меняем в коде; второй замер — только env-override локального прогона.

### Task 2: Seed + cleanup `load_*` users

**Files:**
- Create: `infra/load/seed.mjs`
- Create: `infra/load/cleanup.mjs`

**Interfaces:**
- Consumes: Gateway `http://localhost:3000/api` (глобальный префикс `api`).
- Produces: `infra/load/.tokens.json` вида `[{email, password, cookie}]` + созданные self-чаты; `cleanup.mjs` читает тот же файл.

- [ ] **Step 1: Write `seed.mjs` (минимальная реализация)**

```js
// Контракты: значения из API_ROUTES, шейпы из libs/common zod-схем.
// register: { email, password: /^(?=.*[A-Za-z])(?=.*\d)(?=.*[^\w\s]).{8,}$/, username min 2 }
const BASE = process.env.BASE_URL ?? 'http://localhost:3000';
const N = Number(process.env.SEED_N ?? '50');
const PASS = 'Load1234!x';
const out = [];
for (let i = 0; i < N; i++) {
  const email = `load_${Date.now()}_${i}@example.com`;
  const username = `load_${i}`;
  const reg = await fetch(`${BASE}/api/auth/register`, {
    method: 'POST',
    headers: { 'content-type': 'application/json' },
    body: JSON.stringify({ email, password: PASS, username }),
  });
  if (!reg.ok && reg.status !== 409) throw new Error(`register failed ${reg.status} ${await reg.text()}`);
  out.push({ email, password: PASS, username });
}
await Bun_or_node_write(out);
async function Bun_or_node_write(data) {
  const fs = await import('node:fs');
  fs.writeFileSync(new URL('./.tokens.json', import.meta.url), JSON.stringify(data, null, 2));
  console.log(JSON.stringify({ eventType: 'load_seed_done', count: data.length, hasEmails: data.length > 0 }));
}
```

Примечание: login заблокирован до `isVerified=true` (`auth.service: validateCredentials`). Поэтому после register выполнить test-only SQL (исключение только для сида, в прод-коде запрещено):

```sql
-- polygon_auth
UPDATE credentials SET is_verified = true WHERE email LIKE 'load\\_%@example.com';
```

Затем seed продолжает: login каждого → сохраняет `set-cookie` → `POST /api/chats/self` → сохраняет `chatId` в `.tokens.json`.

Полный seed в реализации обязан содержать 3 фазы: register loop, подсказка про SQL, login+self-chat loop с сохранением `{ email, cookie, chatId }`.

### Task 4: k6 WS scenario

**Files:**
- Create: `infra/load/scenarios/ws-load.js`

**Interfaces:**
- Consumes: `infra/load/.tokens.json` (`[{ cookie, chatId }]`), Gateway WS `ws://localhost:3000/socket.io/?EIO=4&transport=websocket`.
- Produces: WS checks `message:new` получен, `message:send:error` rate < 1%.

- [ ] **Step 1: Write `ws-load.js`**

```js
import ws from 'k6/ws';
import { check, sleep } from 'k6';
const BASE = (__ENV.BASE_URL || 'http://localhost:3000').replace('http', 'ws');
export const options = {
  vus: 100,
  duration: '3m',
  thresholds: { checks: ['rate>0.99'] },
};
export default function () {
  const url = `${BASE}/socket.io/?EIO=4&transport=websocket`;
  const res = ws.connect(url, {}, function (socket) {
    socket.on('open', function () {
      socket.send(JSON.stringify({ type: '2', data: ['message:send', { chatId: 'smoke', type: 'TEXT', text: 'hi' }] }));
    });
    socket.on('message', function (data) {
      if (String(data).includes('message:new')) socket.close();
    });
    socket.setTimeout(function () { socket.close(); }, 5000);
  });
  check(res, { 'ws connected': (r) => r && r.status === 101 });
  sleep(1);
}
```

Примечание: имплементатор обязан подставить реальный `chatId` из `.tokens.json` и куку `access_token` в заголовок `Cookie`, слать `{ chatId, type: 'TEXT', text: 'load <__VU>' }` по протоколу `message:send` из `chat.socket-gateway.ts`, считать `message:send:error` ошибкой.
